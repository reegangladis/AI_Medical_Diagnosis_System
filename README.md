# AI Medical Diagnosis System (MediAI Suite)

Medical AI Diagnosis System is a deep learning-based clinical intelligence platform. It analyzes medical scan images to screen for key conditions, generates clinical reports, offers diagnostic explanations, and allows patients to book specialist appointments.

---

## 🌟 Key Features

1. **Deep Learning Diagnosis**: Detects 7 major pathologies from scan uploads:
   * **Pneumonia** (X-ray scan)
   * **Tuberculosis** (X-ray scan)
   * **Brain Tumor** (MRI scan)
   * **Skin Cancer** (Dermatoscopic image)
   * **Bone Fracture** (X-ray scan)
   * **Lung Cancer** (Categorical: Adenocarcinoma, Large Cell, Squamous, or Normal)
   * **Malaria** (Blood smear cell slide)
2. **Explainable AI (Grad-CAM)**: Generates a colorized attention heatmap overlay showing exactly where the neural network focused to highlight anomalies.
3. **Medical PDF Reports**: Automatically generates download-ready clinical PDF reports with patient info, AI interpretation, and Grad-CAM scans.
4. **Dual LLM Voice Doctor Chatbot**:
   * Powered primarily by the **Gemini API** (`gemini-1.5-flash`) for cloud hosting speed and reliability.
   * Graceful fallback to local **Ollama** (`gemma:2b`) or rule-based medical dialogue engines if keys are not provided.
5. **Hospital Directory & Appointment Booking**: Recommends local specialist doctors (e.g. Pulmonologist, Neurologist) and provides booking slips with interactive maps.
6. **Graceful Simulation/Demo Mode**: If model files (`.h5`) are unavailable at runtime (e.g., Git LFS not configured on the server), the app automatically runs in a fully-functional simulation mode — predictions are deterministic but not AI-powered.

---

## 💻 Tech Stack

* **Backend**: Flask, TensorFlow/Keras, OpenCV (CV2), PostgreSQL (production) / SQLite (local fallback), Flask-SQLAlchemy, Flask-Migrate, ReportLab, python-dotenv
* **Frontend**: HTML5 (Semantic Structure), Vanilla CSS (Responsive Glassmorphism & Mesh Backgrounds), JavaScript (Number counters, mobile nav toggles, buttons ripple effects)
* **Hosting Configuration**: WSGI, Gunicorn, Procfile

## 🚀 Local Installation & Quickstart

### Prerequisites
* Python 3.11+
* pip
* Git LFS (for ML models — see below)
* PostgreSQL (optional — falls back to SQLite automatically)

### Setup Instructions

1. **Clone the Repository**:
   ```bash
   git lfs install   # Required to pull .h5 model files
   git clone <your-repository-url>
   cd medical-ai-diagnosis
   ```

2. **Initialize Virtual Environment**:
   ```bash
   python -m venv venv
   # On Windows:
   .\venv\Scripts\activate
   # On Linux/macOS:
   source venv/bin/activate
   ```

3. **Install Dependencies**:
   ```bash
   pip install -r requirements.txt
   ```

4. **Setup Environment Variables**:
   ```bash
   cp .env.example .env
   # Then edit .env with your values
   ```
   Minimum required for local dev:
   ```env
   SECRET_KEY=any_random_string_for_local_use
   FLASK_ENV=development
   GEMINI_API_KEY=your_gemini_key   # optional, falls back to Ollama
   GOOGLE_MAPS_API_KEY=your_maps_key
   ```

5. **Run Database Migrations**:
   ```bash
   flask db upgrade
   ```
   *(The app also auto-creates tables via `db.create_all()` on startup as a fallback.)*

6. **Run the Application**:
   ```bash
   python wsgi.py
   ```
   Open: [http://127.0.0.1:5000](http://127.0.0.1:5000)

## 📦 Deployment — Render (Recommended)

This project includes a `render.yaml` Blueprint for **one-click deployment** to [Render](https://render.com).

### Option A: One-Click Blueprint Deploy

1. Push this repo to GitHub.
2. Go to [Render Dashboard](https://dashboard.render.com) → **New** → **Blueprint**.
3. Connect your GitHub repo — Render will detect `render.yaml` automatically.
4. Set the following **Environment Variables** manually in the Render dashboard:
   | Variable | Required | Description |
   |---|---|---|
   | `SECRET_KEY` | ✅ Yes | Auto-generated by Blueprint |
   | `FLASK_ENV` | ✅ Yes | Set to `production` |
   | `DATABASE_URL` | ✅ Yes | Auto-set from linked PostgreSQL |
   | `GEMINI_API_KEY` | Optional | Gemini AI chatbot |
   | `GOOGLE_MAPS_API_KEY` | Optional | Hospital map links |
   | `MODELS_DIR` | Optional | `/var/data/models` if using Persistent Disk |

### Option B: Manual Render Web Service

1. **Create Web Service**: Connect your GitHub repo.
2. **Environment**: Python 3
3. **Build Command**:
   ```bash
   pip install -r requirements.txt && flask db upgrade
   ```
4. **Start Command**:
   ```bash
   gunicorn wsgi:app --workers 1 --timeout 120 --bind 0.0.0.0:$PORT
   ```
5. Add a **PostgreSQL** database and link it (sets `DATABASE_URL` automatically).

## 🤖 ML Model Deployment Strategy

The `.h5` model files are tracked via **Git LFS** (`.gitattributes` is configured). There are two approaches:

### Approach 1: Git LFS (Recommended for simplicity)
```bash
# One-time setup
git lfs install
git lfs track "*.h5"

# Push models to your remote (GitHub supports Git LFS)
git add models/
git commit -m "Add ML models via LFS"
git push
```
Render will pull LFS files during build automatically.

### Approach 2: Render Persistent Disk
1. In `render.yaml`, a 5GB persistent disk is configured at `/var/data`.
2. SSH into your Render service and upload model files:
   ```bash
   # From your local machine:
   scp models/*.h5 <render-ssh-host>:/var/data/models/
   ```
3. Set env var `MODELS_DIR=/var/data/models` in Render dashboard.
4. Models persist across deploys — no re-upload needed.

> **Note**: If models are missing, the app runs in **Simulation/Demo Mode** automatically — predictions are deterministic but not AI-powered.

## 🛠️ Troubleshooting

| Issue | Solution |
|---|---|
| `libGL.so.1: cannot open shared object` | Ensure `opencv-python-headless` is in requirements (not `opencv-python`) |
| `SECRET_KEY environment variable is not set` | Set `SECRET_KEY` in your `.env` or Render environment |
| Models loading as `None` | Check `MODELS_DIR` path; app will run in Simulation Mode |
| `psycopg2` SSL errors | Render PostgreSQL requires SSL — already configured in `app.py` |
| Gunicorn worker timeout | Increase `--timeout` or reduce model warm-up operations |
